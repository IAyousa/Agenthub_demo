## 1. 项目概述

### 1.1 项目名称

**AgentHub** — 多 Agent 协作平台

### 1.2 核心功能一句话描述

以 IM 聊天为交互界面，通过主 Agent（Orchestrator）调度多个 AI Agent，在聊天流中生成、预览、部署代码/网页等产物的协作平台。

### 1.3 核心用户场景

- 用户创建聊天会话，选择 Agent（如 Claude Code）
- 通过 WebSocket 实时发送消息给后端
- 后端通过 Agent 网关调用 Python Agent 服务
- Agent 返回流式结果，逐字展示在聊天窗口
- 产物（代码/网页）内联预览，支持编辑和部署

### 1.4 团队画像

| 维度 | 现状 |
|------|------|
| 团队规模 | 4 人，CS 大三学生 |
| 主力语言 | Java，Spring Boot 有实战经验 |

## 2. 技术栈总览

| Vue 3 | ^3.4.0 | 团队熟悉，响应式数据驱动，适合实时交互 |
| Vite | ^5.0 | 快速热更新，开发体验好 |

#### 后端主服务

| 技术 | 版本要求 | 选型理由 |

| Spring Boot | 3.2.x | 团队主力语言，WebSocket 支持成熟 |

#### 基础设施

| 组件 | 版本 | 用途 |
|------|------|------|
| PostgreSQL | 15 | 数据持久化，JSONB 类型适合结构化消息 |
| Docker + Docker Compose | latest | 统一开发环境 |
| 本地文件系统 | - | MVP 阶段产物存储（P1 阶段迁至 MinIO） |
| Java 内存 Map | - | MVP 阶段 WebSocket 会话管理（P1 阶段迁至 Redis） |

### 2.2 MVP 阶段简化策略

| 组件 | MVP 阶段 | P1 阶段 |
|------|---------|---------|
| 数据库 | PostgreSQL（必须） | 同左 |
| 缓存/会话管理 | **Java 内存 ConcurrentHashMap** | Redis（可选） |
| 文件存储 | **本地文件系统 + Spring 静态资源映射** | MinIO |
| Agent 调用方式 | **CLI 子进程（Claude Code / Codex）+ HTTP API（自定义 Agent）** | 同左 |

### 2.3 选型核心原则

1. **团队舒适区优先**：工程侧用 Java/Spring Boot，不强制学习新语言
2. **AI 生态对齐**：Agent 侧用 Python，LangChain 生态的所有教程/示例直接可用
3. **渐进式复杂度**：MVP 用最简单的方案跑通链路，P1/P2 逐步引入高级组件
4. **接口契约解耦**：Java 和 Python 通过 HTTP 通信，各自独立开发测试
