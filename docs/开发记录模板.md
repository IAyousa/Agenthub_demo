## 附：填写指南

### 适用场景

本模板覆盖两种最常见任务类型。不同类型可省略不适用章节。

**类型 A：编码实现型**（如 C1、C6、JPA 数据层搭建、CORS 配置）

```
必填：一(背景) 二(执行过程) 四(验证测试) 五(关键决策) 六(产物清单)
选填：三(技术要点) 七(数据流影响) 八(后续依赖)
```

**类型 B：分析设计型**（如 数据库持久化机制分析、团队任务分配与群聊方案设计）

```
必填：一(背景) 二(执行过程/分析过程) 五(关键决策) 六(产物清单)
选填：三(技术要点) 七(架构影响) 八(后续依赖)
```

### 编写建议

| 原则 | 说明 |
|------|------|
| **记录错误过程** | 失败的尝试和修复过程比成功的结果更有价值。记录"什么错了→为什么→怎么修" |
| **决策附带理由** | 不只写"选择了A"，还要写"为什么没选B"。让后人理解上下文 |
| **代码片段可运行** | 粘贴的代码片段应该是完整的、可以独立理解的最小单元 |
| **测试结果可复现** | 自动化验证写清命令，手动验证写清步骤和预期 |
| **文件路径用相对路径** | 相对于项目根目录，如 `frontend/src/components/chat/MessageInput.vue` |
| **技术讲解面向团队** | 假设读者是同级开发者，用通俗语言解释技术概念，不炫耀术语 |

### 文件命名规范

```
开发过程记录-{简短任务描述}.md

示例：
  开发过程记录-C1-Axios实例配置.md           ← 任务编号 + 描述
  开发过程记录-JPA数据层搭建.md              ← 无编号时只用描述
  开发过程记录-数据库持久化机制分析.md         ← 分析型任务
```

### 存放位置

- 本模板文件位于 `docs/` 目录下，随项目代码一起推送到远程仓库，所有团队成员可见
- 团队成员编写的具体开发记录文档放在 `agent_collaboration/` 目录下（已配置 .gitignore，不推送到远程仓库）
